# 前端更新说明

## 更新内容

### 1. API 接口完全重构
- ✅ 更新为与后端完全匹配的接口结构
- ✅ 支持三种业务类型：车票订单、酒店订单、酒店入驻
- ✅ 添加请求重试机制（最多2次重试）
- ✅ 优化错误处理和用户提示
- ✅ 增加30秒超时设置

### 2. 申请审核页面 (ApplyAudit.tsx)
**新功能：**
- ✅ 支持三种业务类型的完整表单
- ✅ 车票订单：订单ID、车票类型、出发站、到达站、发车时间、乘客信息、订单金额
- ✅ 酒店订单：酒店信息、房间类型、入住/退房时间、入住人信息、订单金额
- ✅ 酒店入驻：酒店信息、营业执照编号
- ✅ 表单验证：必填项检查、身份证号格式验证、金额范围验证
- ✅ 示例数据加载功能
- ✅ 动态表单：根据业务类型显示不同字段

### 3. 审核列表页面 (AuditList.tsx)
**新功能：**
- ✅ 数据统计卡片：待审核、已通过、已驳回、总计
- ✅ 高级筛选：按审核ID、业务类型、审核状态筛选
- ✅ 详细信息展示：根据业务类型显示不同的详情
- ✅ 审核操作：通过/驳回，支持审核备注
- ✅ 状态徽章：不同状态用不同颜色标识
- ✅ 响应式表格：支持横向滚动
- ✅ 分页功能：每页10条记录

### 4. 数据概览页面 (AuditDashboard.tsx)
**新功能：**
- ✅ 实时统计：总量、待审核、审核中、已通过、已驳回、已撤销
- ✅ 业务类型分布统计
- ✅ 审核通过率和驳回率计算
- ✅ 自动刷新：每30秒更新一次数据
- ✅ 图标化展示：使用Ant Design图标

### 5. 稳定性优化
- ✅ 请求重试机制：网络错误和5xx错误自动重试
- ✅ 错误日志记录：详细的错误信息记录到控制台
- ✅ 友好的错误提示：根据不同错误类型显示不同提示
- ✅ 加载状态管理：防止重复提交
- ✅ 表单重置：提交成功后自动清空表单

## 启动方式

### 开发环境
```bash
cd frontend
npm install
npm run dev
```
访问：http://localhost:3000

### 生产构建
```bash
cd frontend
npm run build
```
构建产物在 `dist/` 目录

## 后端接口要求
后端服务需要运行在 `http://localhost:8080`

### 接口列表
1. **POST /api/v1/audit/submit** - 提交审核申请
2. **GET /api/v1/audit/list** - 查询审核列表
3. **POST /api/v1/audit/process** - 处理审核（通过/驳回）

## 使用说明

### 1. 提交审核申请
1. 选择业务类型（车票订单/酒店订单/酒店入驻）
2. 点击"加载示例数据"可快速填充测试数据
3. 填写必填字段
4. 点击"立即提交"

### 2. 查看审核列表
1. 查看统计卡片了解整体情况
2. 使用筛选功能查找特定审核记录
3. 点击"详情"查看完整信息
4. 点击"审核"进行审核操作

### 3. 审核操作
1. 在列表中点击"审核"按钮
2. 选择"通过"或"驳回"
3. 填写审核备注（可选）
4. 点击"确认提交"

### 4. 数据概览
- 自动显示各项统计数据
- 每30秒自动刷新
- 查看业务类型分布
- 查看审核通过率和驳回率

## 注意事项
1. 确保后端服务已启动（端口8080）
2. 身份证号必须是18位有效格式
3. 订单金额必须大于0
4. 车票发车时间、酒店入住/退房时间会自动转换为UTC时间
5. 所有必填字段都有表单验证

## 已知问题
- 中文字符在某些终端可能显示为乱码（这是终端编码问题，不影响功能）
- 大数据量时建议使用筛选功能以提高性能
